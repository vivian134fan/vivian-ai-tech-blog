## 導讀

同一句話，AI 第六輪就忘。原因並非出錯，而是每次回答都重新計算。11 月 23 日，上海企業記憶張量發布原生記憶模型 MemT 1.0 Pro，將快慢記憶直接寫入模型。官方稱 Token 消耗降低六至七成，任務完成率提升約三成。上述數字由廠方提供，第三方實測尚待公布。以下拆解回應不一致的成因，以及快慢記憶分層的技術含義。

> 本文首發於 AI 科技資訊前沿博客，屬《AI 看得見》視覺知識欄目的文字版。

## 新聞內容

### 一、回應不一致，源於逐次重新計算

用戶過往經驗是：同一要求反覆提出，模型回應未必一致。直觀解讀是模型出錯，或未有妥善保存對話。實際機制更接近以下情況：模型每一次回答，都按當前輸入重新計算概率分佈，而非直接從既有記憶讀取答案。

換句話說，模型並不保存一段可回溯的對話紀錄，而是每次都重新走一遍路徑。所謂「忘記」，是這個計算過程的外在表現，並非故障。這也解釋了為何同一問題在不同輪次會得到不同回應——計算起點已隨上下文改變。

### 二、現有做法依賴外掛上下文

業界處理記憶問題的主流做法，是外掛上下文窗口：把過往對話摘要或關鍵資訊，連同當前問題一併送入模型。每次呼叫都需要重新讀取這份聊天紀錄，佔用 Token，也受限於窗口長度。

這種做法的缺點有三：其一，Token 消耗隨對話長度上升；其二，摘要過程可能丟失細節；其三，長期偏好與短期 context 混在同一層，難以取捨。 MemT 1.0 Pro 的出發點，正是將記憶由外掛改為原生。

### 三、快慢記憶分層寫入模型

據 11 月 23 日發布資料，MemT 1.0 Pro 把記憶分為兩層：

- **快記憶**：記錄即時偏好與當前對話脈絡，邊聊邊更新；
- **慢記憶**：沉澱長期習慣與知識，跨對話保留。

兩層分工的技術含義，在於把「當下要用的資訊」與「長期要留的資訊」分開處理。快記憶服務即時回應，慢記憶提供穩定背景，兩者不必爭用同一個上下文窗口。這是「記憶原生」與「外掛上下文」的根本分別。

### 四、官方數字與第三方驗證

官方稱 Token 消耗降低六至七成，任務完成率提升約三成。記憶張量首席執行官熊飛宇表示，記憶是 Agent 的關鍵能力。須強調，上述數字由廠方提供，第三方實測尚待公布，讀者應留意數字與獨立驗證之間的落差。

對香港企業而言，此項發布的實質意義不在於排名，而在於成本結構：若記憶由外掛改為原生，長對話場景的 Token 開支有機會下降。不過，實際節省幅度仍須按具體使用模式實測，不宜直接套用廠方數字。

## 結語

記憶，才是 Agent 的關鍵。算力決定模型能算多快，記憶決定模型能否承接連續任務。11 月 23 日的發布，把這個問題由工程技巧推回模型底層。接下來的關鍵，是第三方實測能否支持官方說法。
